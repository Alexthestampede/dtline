## Critical Conventions

### Scale Factor System (Causes Server Crashes If Wrong)
- `ImageGenerationConfig(width=512, height=512)` takes **pixels**
- The client converts to scale units internally: `scale = pixels // 64`
- For SDXL models: `scale = pixels // 128`
- Direct FlatBuffer users must do this conversion manually
- Server crash symptom: `[cnnp_reshape_build] dim: (2, 262144, 320)` (should be 4096)

### Generated Code — Do Not Edit
- `imageService_pb2.py` / `imageService_pb2_grpc.py` — generated by `grpcio-tools` from `imageService.proto`
  - Regenerate locally: `python -m grpc_tools.protoc -I. --python_out=. --grpc_python_out=. imageService.proto`
- `GenerationConfiguration.py` — auto-generated FlatBuffer schema (see comment at line 1)
- Edits to proto schema go to [drawthingsai/draw-things-community](https://github.com/drawthingsai/draw-things-community)
  - The upstream proto + `config.fbs` live in the repo; the local `draw-things-community/` clone is the reference

### Response Tensors Are (Likely) fpzip-Compressed
**The server probably sends fpzip-compressed tensors for everything** (images, frames, masks, hints) unless started with `--no-response-compression`.
- Detect via header magic `[0]`: `1012247` = fpzip float32, `0` = uncompressed float16
- `tensor_decoder.decode_tensor()` auto-detects and handles both — but fpzip is required
- This only applies to the **response** side; input images you send stay uncompressed float16 for edit/kontext models

### Edit/Kontext Models — Required Settings
- `strength=1.0` is **mandatory** (setting lower corrupts the reference encoding)
- Input image must match `width` × `height` exactly
- Must encode as uncompressed float16 (`compress=False` in `tensor_encoder`)
- `_encode_image()` does this automatically; direct callers must pass `compress=False`

### Tensor Format (CCV NNC)
```
[68-byte header][pixel data]
Header: 17 x uint32 little-endian
  [0] magic: 0 = uncompressed float16, 1012247 = fpzip float32
  [1] memory_type: 0x1 = CPU
  [2] format: 0x2 = NHWC
  [3] datatype: 0x20000 = CCV_16F, 0x10000 = CCV_32F
  [5] batch=1, [6] height, [7] width, [8] channels=3
Pixel formula: float_value = uint8 / 127.5 - 1.0  (range -1.0 to +1.0)
```

### TLS Certificate — Required for Secure Connections
**TLS will fail without the Draw Things root CA certificate.** Download `root_ca.crt` from:
https://github.com/drawthingsai/draw-things-community/tree/main/Libraries/BinaryResources/Resources

Place it as `root_ca.crt` in the working directory, or pass the path via `ssl_cert_path`.

### gRPC Channel Options
The client sets large message lengths (32 MB) and HTTP/2 keepalive params. TLS is the default; use `insecure=True` for plain TCP. Self-signed certs: pass `ssl_cert_path` or place `server_cert.pem` in the working directory.

## Important Constraints from README

1. **Kontext/edit models**: `strength=1.0`, input dims = output dims, uncompressed float16
2. **FLUX guidance**: Use `guidance_embed` (default 3.5), not `cfg_scale` (set to 1.0)
3. **TeaCache**: ~20-30% speedup for FLUX at `tea_cache_threshold=0.06`
4. **Tiled diffusion**: Required for images > 1024×1024 to avoid OOM
5. **fpzip required**: `pip install fpzip` or decoded images will raise an error
6. **Video assembly (optional)**: `pip install imageio imageio-ffmpeg` for `save_video()`

## Reference Images / Moodboard Support

Edit models (FLUX.2 Klein, etc.) can use multiple reference images for composition:

```python
from drawthings_client import ReferenceImage

images = client.generate_image(
    prompt="the person from reference 3, wearing clothes from reference 2, on the beach from reference 1",
    config=config,
    reference_images=[
        ReferenceImage(image="beach.jpg", weight=0.33, hint_type="shuffle"),
        ReferenceImage(image="clothes.jpg", weight=0.33, hint_type="shuffle"),
        ReferenceImage(image="person.jpg", weight=0.34, hint_type="shuffle"),
    ]
)
```

### Hint Types

| Type | Use Case |
|------|----------|
| `"shuffle"` | Edit/kontext models (FLUX.2 Klein) — images are VAE-encoded as visual tokens |
| `"ipadapterplus"` | IP-Adapter style conditioning |
| `"ipadapterfull"` | Full IP-Adapter |
| `"depth"`, `"canny"`, etc. | ControlNet preprocessor hints |

For edit models, use `"shuffle"` with `strength=1.0` in the config.

## Video Generation Notes

- Use `generate_media()` to capture frames **and** audio (`GenerationResult.images` / `.audio`); `generate_image()` still returns just `List[bytes]` and discards audio (kept for backward compatibility).
- `save_video()` muxes frames + audio into MP4; requires optional `imageio`/`imageio-ffmpeg` deps.
- **Audio is a tensor too**: each `GenerationResult.audio` entry is a reassembled fpzip-compressed CCV tensor, shape `(channels, samples)` (stereo `(2, N)`), values in `[-1.0, 1.0]` — chunked exactly like image tensors (accumulate on MORE_CHUNKS, decode on LAST_CHUNK; upstream decodes each element of `generatedAudio` individually).
- `tensor_decoder.decode_audio_tensor()` converts an audio tensor to interleaved float32 PCM; `save_video()` calls it per entry.
- Sample rate: 48 kHz for LTX 2.3, 24 kHz default (upstream `ModelZoo.audioSampleRateForModel`).
- LTX VAE ratios differ from image models (server uses `startScaleFactor = 32` and doubles scale); pass pixel dims in multiples of 64.
- Server forces batch size 1 for video models regardless of config.
